# SayaShop Backend (Node.js / Express)

Настоящий сервер на Node.js вместо демо-страницы `backend.html`. Хранит данные
в файле `data/db.json` (создаётся автоматически при первом запуске) — это уже
**общая база для всех покупателей и устройств**, а не localStorage браузера.

## Запуск

Нужен установленный Node.js 18+ (https://nodejs.org).

```bash
cd backend
cp .env.example .env    # создать файл настроек из примера
nano .env                # поменять ADMIN_PASSWORD и остальное под себя
npm install
npm start
```

Сервер поднимется на `http://localhost:4000` (или на порту из `.env`).
Магазин: `/frontend.html`, админка: `/admin.html`. Все эндпоинты API — под `/api`.

Для разработки с автоперезапуском при изменении файлов:
```bash
npm run dev
```

## Настройки (.env)

Файл `.env` рядом с `server.js` — скопируйте его из `.env.example`.
Если `.env` не создавать, сервер запустится со значениями по умолчанию
(см. колонку ниже), но для боевого сервера так делать не стоит.

| Переменная | По умолчанию | Описание |
|---|---|---|
| `PORT` | `4000` | порт, на котором слушает сервер |
| `NODE_ENV` | `development` | `production` на боевом сервере |
| `CORS_ORIGIN` | `*` | какие домены могут обращаться к API; `*` — любые (только для теста). На проде указывайте точный домен(ы) через запятую: `https://sayashop.tj,https://www.sayashop.tj` |
| `ADMIN_PHONE` | `admin` | логин администратора |
| `ADMIN_PASSWORD` | `rahimov` | пароль администратора — **обязательно смените перед публикацией** |
| `UPLOAD_LIMIT_MB` | `10` | максимальный размер одного файла (фото товара, чек оплаты) |

`ADMIN_PHONE`/`ADMIN_PASSWORD` применяются только при **первом** запуске,
когда создаётся `data/db.json` — это создание самого первого аккаунта-админа.
Если вы поменяете пароль в `.env` уже после первого запуска, учётка в базе
не обновится сама: либо удалите `data/db.json` и запустите заново (тогда
все остальные данные тоже сотрутся), либо смените пароль через админку
(раздел профиля) или напрямую в `data/db.json`.

## Структура проекта

```
backend/
  server.js         — точка входа, настройка Express
  db.js             — файловая "база данных" (data/db.json создаётся сама)
  routes.js         — все эндпоинты API
  .env              — ваши настройки (создаётся из .env.example, в git не попадает)
  .env.example      — пример настроек с описанием
  data/db.json      — сами данные (создаётся автоматически)
  public/           — frontend.html и admin.html (раздаются этим же сервером)
  uploads/          — загруженные фото товаров и чеки оплаты
```

## Авторизация

Простая токен-авторизация (без сторонних сервисов): при регистрации/входе
сервер выдаёт `token`, который нужно передавать в заголовке:

```
Authorization: Bearer <token>
```

Пароли хранятся хешированными (bcrypt), а не в открытом виде. Логин и пароль
администратора нигде в HTML/JS не хранятся — только на сервере, в `.env`.

Чтобы сделать покупателя администратором вручную — откройте `data/db.json`
и поставьте `"isAdmin": true` у нужного пользователя.

## Деплой на Render (бесплатный тариф)

1. **Root Directory** в настройках сервиса на Render — обязательно `backend`
   (там, где лежит `package.json`), а не корень репозитория. Если указать
   неправильно, Render не найдёт `package.json` и/или папку `public/`, и
   сайт/эндпоинты будут отдавать 404.
2. **Build Command**: `npm install`
3. **Start Command**: `node server.js` (или `npm start`)
4. **Environment variables** — задаются в разделе *Environment* на Render,
   не файлом `.env` (файл `.env` специально в `.gitignore` и в репозиторий
   не попадает — так пароль не светится в публичном git). Добавьте там:
   `ADMIN_PHONE`, `ADMIN_PASSWORD`, `CORS_ORIGIN` (ваш домен), `UPLOAD_LIMIT_MB`.
   Если их не задать, сервер всё равно запустится — но с паролем по умолчанию
   (`admin` / `rahimov`), это небезопасно для открытого в интернет сайта.
5. Убедитесь, что папка `public/` реально попала в git:
   ```bash
   git ls-files | grep public
   ```
   Если команда ничего не выводит — `frontend.html`/`admin.html` не
   закоммичены, и открытие сайта по корневому адресу будет отдавать
   `{"error":"Эндпоинт не найден"}` вместо магазина.
6. Данные (`data/db.json`, `uploads/`) на бесплатном Render **не сохраняются
   между деплоями** — это обычная файловая система контейнера, она
   пересоздаётся при каждом новом деплое. Для теста это нормально, но для
   реального магазина на free-тарифе Render так делать нельзя — нужен либо
   платный план с постоянным диском (Persistent Disk), либо вынести
   данные во внешнюю БД.

### Почему видно `{"error":"Эндпоинт не найден"}`

Это ответ сервера на запрос пути, которого у него нет (обработчик 404 в
`server.js`). Самые частые причины:
- в git не попала папка `public/` (см. пункт 5 выше) — тогда 404 будет
  даже на корневом адресе сайта;
- **Root Directory** в Render указывает не на `backend/`;
- опечатка в адресе (например, обращение к `/api/product` вместо
  `/api/products`) — сверьтесь со списком эндпоинтов выше.

Если сервер вообще не отвечает (зависает, а не выдаёт 404) — скорее всего
это просто "просыпание" после сна, см. ниже.

## Бесплатный Render засыпает — как не терять первых посетителей

На бесплатном тарифе Render сервис "усыпляется" после ~15 минут без
входящих запросов, а разбудить его занимает до minуты. Это касается и
API, и самого сайта (он тоже раздаётся этим сервером). Сделано два фикса:

1. **На клиенте** — `public/frontend.html` и `public/admin.html` перед
   показом магазина/входа сами опрашивают `GET /api/health` и показывают
   экран "Просыпаемся…", пока сервер не ответит (до ~60 секунд, с кнопкой
   "Повторить", если не вышло). Это уже работает из коробки, ничего
   настраивать не нужно.
2. **Снаружи (рекомендуется)** — чтобы сервер вообще не засыпал, настройте
   бесплатный внешний пинг каждые 10 минут на https://cron-job.org:
   - зарегистрируйтесь (бесплатно, email);
   - "Create cronjob" → URL: `https://sayashop.onrender.com/api/health`;
   - Schedule: каждые 10 минут (`*/10 * * * *`);
   - сохраните.

   Так сервис будет получать внешний запрос раньше, чем успеет уснуть, и
   первые посетители не будут ждать пробуждения. (Альтернатива — UptimeRobot,
   принцип тот же: бесплатный мониторинг, который сам и есть ваш "будильник".)

## Запуск на боевом сервере (production)

Коротко, по шагам — для Ubuntu/Debian-сервера:

1. Установите Node.js 18+ и склонируйте/загрузите проект на сервер.
2. `cd backend && cp .env.example .env`, пропишите реальные `ADMIN_PASSWORD`
   и `CORS_ORIGIN` (точный домен сайта, не `*`), `npm install`.
3. Запускайте не напрямую через `npm start`, а через менеджер процессов —
   он сам перезапустит сервер при падении и при перезагрузке сервера:
   ```bash
   npm install -g pm2
   pm2 start server.js --name sayashop
   pm2 save
   pm2 startup     # выполнить команду, которую pm2 покажет в ответ
   ```
4. Поставьте nginx перед сервером как обратный прокси (и для HTTPS):
   ```nginx
   server {
     listen 80;
     server_name sayashop.tj www.sayashop.tj;
     location / {
       proxy_pass http://localhost:4000;
       proxy_set_header Host $host;
       proxy_set_header X-Real-IP $remote_addr;
     }
   }
   ```
   Затем включите HTTPS через Certbot: `certbot --nginx -d sayashop.tj -d www.sayashop.tj`.
5. Файлы в `uploads/` и `data/db.json` — это ваши живые данные, делайте их
   резервную копию регулярно (это просто папка/файл, можно копировать как есть).

## Важно

Это по-прежнему демонстрационный сервер: без rate-limit, без email/SMS-
подтверждения телефона, без разграничения ролей через отдельную таблицу.
Для серьёзной нагрузки стоит добавить настоящую БД (PostgreSQL/MongoDB)
вместо файла `db.json` — он читается и перезаписывается целиком на каждый
запрос, что нормально для сотен-тысяч товаров/заказов, но не для огромных
объёмов.

## Подключение frontend.html / admin.html

Файлы `public/frontend.html` и `public/admin.html` уже работают через этот API.
Сервер раздаёт их сам по тем же `PORT`/домену: `/frontend.html` и `/admin.html`.
Адрес API определяется автоматически (переменная `API_BASE` в начале скрипта
каждого файла) — отдельно настраивать не нужно.
